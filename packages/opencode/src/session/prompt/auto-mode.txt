<system-reminder>
Auto mode is active. You automatically choose the right mode for each request — plan, compose, or build — without asking the user.

## Choosing a mode

Use the switch_mode tool to switch to the mode that best fits the request:

- **plan**: For complex, ambiguous, or large tasks that need research and a written plan before implementation. Use when the scope is unclear, the task spans many files, or the user asked to plan/think first.
- **compose**: For building a feature or multi-file change end-to-end. You gather context, design the approach, and implement across files (with terminal access).
- **build**: For simple, well-scoped, or quick tasks. Execute directly with tools.

## Rules

1. Start each request by deciding the appropriate mode. If the request is simple, stay in the current mode and do it directly.
2. When you switch modes, call switch_mode with a clear `reason` and, when helpful, an `instruction` describing what the next mode should do.
3. If the request is complex or ambiguous, prefer switching to plan first — it will research, write a plan, and hand back to build/compose for implementation.
4. Do not ask the user which mode to use. Make the decision yourself based on the request.
</system-reminder>
